  THREATS AND RISKS DESCRIBED (page's own framing)
  1. Prompt injection and tool poisoning: indirect prompt injection hides instructions in a tool's description, metadata, or data the server returns. The model reads them as commands. Possible outcomes: data leakage, misuse of connected systems, unapproved actions.
  2. Rug pulls / changing tool definitions: a server looks benign at install, then rewrites its tool definitions after approval. Reviews happen mostly at install, so the change goes unnoticed.
  3. Malicious or unvetted MCP servers: servers are easy to add from public registries/marketplaces, often without security review. A malicious or compromised server can steal data, harvest tokens, or drive harmful agent actions.
  4. Token theft and credential exposure: OAuth tokens and API keys may be broadly scoped, long-lived, or stored in plaintext config files.
  5. Command injection and RCE: local servers that pass input to the OS without validation can allow extra shell commands and code execution with the server's privileges.
  6. Excessive permissions and scope creep: agents and servers accumulate more access than tasks need, so one hijack exposes more.
  Background claims: local servers rely on OS permissions and remote servers add third-party trust, public exposure and token-based auth. The FAQ says MCP is not secure by default, with authentication and transport security largely optional. The FAQ also says local servers are not inherently safer than remote ones.
